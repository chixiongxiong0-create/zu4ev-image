# ZU4EV Mono RAW10 动态 DPC 设计

## 目标与方案

面向 SC130GS 1280×1024 @ 120 fps，以每拍两个 RAW10 像素在线判定孤立亮坏点和暗坏点。峰值输入约 157.3 Mpixel/s，对应至少 78.64 M 个有效双像素拍每秒。沿用现有像素时钟和数据接口，无需坐标表。

Brigates 的 3×3 极值判定可直接移植算法思路。第一版增加邻域平坦度门控，优先减少纹理和边缘误修，并采用最平滑方向的对称邻点均值替换中心点。严格区分观察与修复。真实单像素亮点和同形热坏点在单帧 3×3 窗口内可以完全相同，修复模式无法保证保留它们。已知坏点簇仍由现有静态 DPC 处理。

数据路径为 RAW10 → FFC → 静态 DPC → 动态 DPC → AE/BLC/LTM。静态表可以禁用或为空。动态 DPC 的两个像素均从同一份输入邻域判定，动态修复结果不写回行缓存。Bayer 需要独立的同色邻域设计。

## 判定与修复

取 3×3 窗口的中心 `p` 和其余八个邻点，求 `lo=min(N)` 和 `hi=max(N)`。

| 条件 | 运算 |
|---|---|
| 邻域平坦 | `hi - lo <= flat_limit` |
| 亮坏点候选 | 平坦且亮检测开启且 `p > hi + hot_margin` |
| 暗坏点候选 | 平坦且暗检测开启且 `p + cold_margin < lo` |
| 修复值 | 在水平、垂直、两条对角线的对称邻点对中选 `abs(a-b)` 最小的一对，输出 `(a+b+1)>>1` |

方向梯度相同时按水平、垂直、左上到右下、右上到左下排序。像素和阈值均为无符号 10 位，比较的加法和取平均的加法均先零扩展到 11 位。八个邻点的极值差及方向差为 10 位。使用严格不等式，恰好等于阈值时保留原像素。四周一圈像素直接透传且不计候选。

建议从 `hot_margin=32`、`cold_margin=32`、`flat_limit=24` 开始观察。这些是仿真和图像筛查的起点。板上已确认的热坏点可能弱于初始阈值，应以 FFC 后的视频样本和实际曝光增益调整。

## 双像素数据通路

| 单元 | 职责 |
|---|---|
| `dpc_dynamic_window` | 按 `s_valid` 写入像素对，检查几何和帧标记。四个独立的同步行 RAM 按跨帧连续行号轮转，每个 640×20 bit。读端独立推进 |
| `dpc_dynamic_kernel` | 双通道并行。流水依次寄存邻域极值及四方向差、阈值判定及最佳邻点对、舍入均值及输出选择。像素、帧标记和配置同步传递 |
| `dpc_dynamic_raw10` | 连接窗口与判定核，管理配置、计数、故障输出和恢复 |

读端按行按列出队。中心行及同帧所需的相邻行都写完后，从下一拍开始连续发出该行的 RAM 读请求。一拍最多读取三个不同的行 bank 并写入第四个。写入首对时撤销旧行标记，写入合法 EOL 后发布新的完成标记。读端到达行尾后释放上一行，保留中心行供同帧下一行使用。首行和末行忽略缺失的邻行，输出仍保留原始中心数据。

三行 RAM 各自保存上一像素对，并利用下一像素对展开水平邻点。例如当前对为 `(x,x+1)`，两条 lane 分别取 `[x-1,x,x+1]` 和 `[x,x+1,x+2]`。行尾对在下一拍自行发出，右边界 lane 走旁路，因此可以与下一行首对的接收重叠。行首清理横向历史。上一帧末行的窗口不得引用下一帧首行。

连续输入时，首个输出约在 1280 个双像素拍加窗口和判定流水后出现。输入空洞会延长等待时间。末行在 EOF 后独立排空。读请求按每拍一对推进，不在换行处插空拍。RAM 一共 51,200 bit，1280 宽度下估算约 4 个 BRAM36 等效块，以综合映射为准。现有全工程验证记录为 116.5/128 BRAM、建立余量 +0.107 ns，需要重新确认布线和下游峰值承载。

## 接口、配置和异常

- 沿用 20 位数据及 `valid/SOF/EOL/packet_error/global_fault`，不增加 `ready` 或新时钟。输入只在有效拍推进，EOL 必须落在第 640 对。启用、观察、旁路都使用同一窗口延迟，切换时不会因快慢路径交叉而丢帧。
- 上电默认旁路。观察模式保留输入并记录候选。修复模式只替换满足条件的内区像素。沿用 ISP 同步配置桥，在 `0x3160–0x318C` 预留独立寄存器，不与静态 DPC 地址重叠。
- 写入影子配置后提交，提交时锁存完整快照，在动态级发出该帧首个读请求时生效。待提交期间拒绝新的提交和配置写，提供应用序号和活动配置读回。同拍提交与帧首时，新配置应用于之后的帧。
- 按完整输出帧发布亮、暗候选数和实际修复数，同时记录故障事件。错误帧不更新上一个完整帧的计数。旁路模式统计为零，观察模式修复数为零。
- 复位或输入故障、非法 SOF/EOL、缓存冲突时取消所有排队行和流水有效标记，发出故障标记，等待干净的 SOF。RAM 保留物理内容，清空行有效标记后禁止读取旧数据。故障优先于读写、配置生效及计数发布。

| ISP 偏移 | 拟定用途 |
|---|---|
| `0x3160` | 模块 ID |
| `0x3164` | 影子模式和亮、暗检测使能 |
| `0x3168` | 影子阈值，按 10 位依次打包亮、暗、平坦度 |
| `0x316C` | 写 1 提交配置 |
| `0x3170` / `0x3174` | 活动模式和待生效标记 / 活动阈值 |
| `0x3178` / `0x317C` | 应用序号 / 最近完成帧序号 |
| `0x3180` / `0x3184` / `0x3188` | 最近完成帧的亮候选 / 暗候选 / 修复计数 |
| `0x318C` | 累计故障事件数 |

## 验收

1. 对照独立整数参考模型，覆盖两个 lane、亮暗阈值临界、满量程、平坦度临界、四个方向和同梯度、孤立真亮点、阶跃边缘、细线、纹理及坏点簇。
2. 跑 1280×1024 连续多帧和随机输入空洞。逐拍核对数据、SOF/EOL、每帧像素数、行尾排空、无间隔接帧、bank 占用及同址冲突。故障覆盖接收中、最后一行排空时和配置待提交时。
3. 验证旁路与观察逐位一致、帧首配置原子切换、静态 DPC 寄存器兼容，以及 AXI 读写停顿和非法写。
4. 综合布线检查行 RAM 映射、像素域时序及现有下游 FIFO 峰值。用实际暗场、均匀亮场和含真实点光源的画面先跑观察，再量化修复模式的命中和误修，验证 120 fps 链路。
