# R5 camera auto exposure

The R5 bare metal program controls the SC130GS through PS IIC0 routed over EMIO to F13/E13. The bus runs at 400 kHz: the SC130GS V2.6 timing table and the Zynq UltraScale+ PS I2C specification both limit the bus to fast mode. The board has 4.7 kΩ pullups to 3.3 V. GPIO software I2C is no longer used.

The older Linux `sensorctl` uses GPIO pins that are no longer connected to the sensor bus in this design. Its commands cannot control this image and its lock does not coordinate with R5. R5 is the sole owner of IIC0 while AE is active.

The CSI controller reports FE through its sticky status register. The PL control master reads and clears that bit before forwarding an event across the clock boundary to `ae_fe_event`; R5 acknowledges the resulting level interrupt with a GPIO output toggle. The FE sequence counts delivered notifications, not necessarily every physical FE: multiple events can coalesce before a clear, including in the read-to-clear interval. Its timestamp includes register service and clock-crossing latency and is not the CSI packet arrival time. FE and AXI video SOF counts are registered as Gray code at the source and decoded by R5. The AXI video SOF is the first output pixel; it is not a direct measurement of the sensor's CSI FS short packet. R5 starts an exposure transaction after AXI SOF and checks that the FE count has not advanced before or during the two consecutive exposure writes. It also checks that the AXI SOF count did not change. These checks cannot establish that a write finishes before the physical FE or sensor latch boundary when FE notification is delayed. There is no confirmed SC130GS group hold command in the available sensor documentation, so the program stops AE on any partial write, readback mismatch, or detected boundary crossing. A fine gain change is a single register write. A failed second byte may already have left the sensor with a partially updated exposure; stopping AE detects this condition but cannot undo it atomically.

The AE core uses the ISP RAW10 black-subtracted mean, exposure first when dark, fine gain first when bright, a ±8 deadband around 96, and a four FE holdoff after a write to account for N+2 latency. `test_ae_core.c` and `test_ae_loop.c` exercise the policy and delayed response on a host compiler.

The application is linked entirely into R5 ATCM and BTCM with `lscript.ld`; it does not use Linux DDR. Build a Vitis 2025.1 standalone R5 domain from the matching XSA and import `main.c`, `ae_core.c`, and `ae_core.h`. Add the directory containing `ae_core.h` to the compiler include paths. Use `lscript.ld` for the application linker script. The RAM boot image adds its ELF as a `destination_cpu=r5-0` partition after the bitstream. Do not use an older bitstream with this application: the FE IRQ and IIC EMIO endpoints must match.

Host tests can be rebuilt from this directory with `gcc -std=c11 -Wall -Wextra -I. ae_core.c test_ae_core.c -o test_ae_core` and the same command using `test_ae_loop.c`. The FE testbench is `sim/ae_stats/tb_fe_event.sv` and should be compiled together with `rtl/sensor/ae_fe_event.sv`. `tools/recreate_project.tcl` and `tools/build_platform.tcl` rebuild the Vivado design in their configured directories. `boot/build_boot_bin.ps1` accepts `-R5AeElf`, and `tools/ram_boot_ltm.tcl` stages the resulting image and FIT in DDR for temporary JTAG boot.

The core entry points are `sc130_ae_core_init`, `sc130_ae_core_propose`, and `sc130_ae_core_commit`. The proposal result is an `ae_change` value, not a success/failure status. The R5 hardware access and FSBL sensor functions return zero on success and minus one on failure; FSBL pipeline and vendor functions retain their own existing contracts. The host tests `test_sensor_status.c` and `test_sensor_start.c` exercise sensor IIC success/failure and FSBL handoff decisions using `test_stubs/`.

This revision has not been validated on hardware. In particular, verify PS IIC ACK and measured SCL timing, interrupt routing, actual FE-to-SOF and IRQ-to-write timing, non-crossing exposure writes, N+2 behavior, and closed-loop convergence before relying on it. Registered Gray counters reduce multi-bit transition ambiguity; their complete PS input path still needs board and CDC verification.

For board diagnostics, read the ELF symbols `ae_log` and `ae_records` through JTAG while R5 is running. `ae_log.magic` is `0x41453552`; fault 0 means running. Each record includes FE and ISP sequence numbers, mean, exposure/gain, SOF count around the write, IRQ and IIC PMU cycle timestamps, FE-to-SOF PL cycles, IIC rate, and a fault code. The R5 cycle clock configured by `ps_system.tcl` is 525 MHz and the video clock is 200 MHz. The ring holds 512 records, so collect it promptly during a test.

Fault codes are 1 IIC initialization, 2 interrupt controller initialization, 3 initial sensor read, 4 sensor mode, 5 IIC write, 6 readback mismatch, 7 exposure write crossing SOF, 8 SOF timeout, 9 no FE for approximately one second, 10 invalid or unchanged statistics for more than 120 received FE events, and 11 FE interrupt acknowledge timeout. These thresholds and the reported clock rates are configuration based until measured on the target.
