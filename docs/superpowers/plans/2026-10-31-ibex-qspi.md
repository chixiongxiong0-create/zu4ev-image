# Ibex QSPI Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for this bounded packaging task.

**Goal:** Build a reviewable QSPI image that automatically starts the tested v3 Ibex platform.

**Architecture:** Preserve the existing FSBL/PMUFW/ATF/U-Boot/kernel/DT and flash layout.
Overlay v3 Linux software and a sequential startup coordinator; build BOOT.BIN/FIT
and a combined image in an independent Ibex delivery directory.

**Tech Stack:** Python, POSIX shell, Bootgen, mkimage/dumpimage/fdtget, WSL.

**Spec:** `docs/superpowers/specs/2026-10-31-ibex-qspi-design.md`.

## Global Constraints

- Original ZU4EV source/artifacts are read-only; no R5 partition.
- BOOT at 0, FIT at 0xc00000, 32 MiB total; preserve all rootfs cpio streams.
- Only Terra operates hardware, flash and reboot; retain the USB error risk.

## Review Focus

- Device nodes in a second archive must survive the overlay.
- PS profile failure must prevent handoff; bridge death must prevent handoff.
- Partial handoff failure must request bounded safe stop, with no start retry.
- Input/hash mismatches and image size overflow must fail before delivery.
- Final FIT kernel/DT/rootfs hashes must match extracted payloads.
