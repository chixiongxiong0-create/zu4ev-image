# ZU4EV 定版记录

2026-11-25 冻结当前源码与关闭 ILA 后的已布线设计，版本标记为 `zu4ev-final-20261125`。器件为 XCZU4EV-SFVC784-2-I，工具为 Vivado 2025.1。

## 配置

- Mono RAW10 双像素流，1280×1024。
- FFC、静态 DPC、动态 DPC、AE、BLC/LTM、TNR、NV12/VCU 集成。
- `ENABLE_CAMERA_ILA=0` 和 `ENABLE_UVC_ILA=0`，保留 GPIO 状态、统计快照和 AE 事件。
- 动态 DPC 复位后处于旁路模式，寄存器可切换观察和修复模式。

## 当前构建

所有路径相对仓库根目录。

| 文件或目录 | 用途 |
|---|---|
| `build/dpc/project/dpc.xpr` | 当前 Vivado 工程及其源 IP、缓存和综合布线输出 |
| `build/dpc/camera_top.bit` | 从 2026-11-11 已布线检查点生成的当前 bitstream |
| `build/dpc/camera_top.ltx` | 与当前设计对应的调试探针描述 |
| `build/dpc/inputs/` | 启动 ROM、Tone 初始化表和板级约束 |
| `build/dpc/recreate_project.tcl` | Vivado 导出的工程重建脚本 |
| `build/dpc/verification/` | 本次回归日志及清理清单 |
| `build/dpc/manifest.json` | 代码版本、构建产物和输入文件的 SHA-256 |

工程的运行输入已从旧 FFC/H.264 构建目录迁入 `inputs/`，迁移前后文件哈希一致。两个 Tone IP 的系数路径通过 Vivado 更新并重新生成输出。路径迁移会令既有 run 显示 Out-of-date；本次保留的是迁移前完成的物理实现，bitstream 与该检查点对应。需要重新综合时使用当前工程或导出的脚本。

重建脚本从自身目录定位输入和仓库源码，在运行它的工作目录下创建 `dpc` 工程。请在空目录中运行。当前工程的完整 `dpc.srcs`、`dpc.gen`、`dpc.cache` 和 `dpc.runs` 均随本地构建保留。

最新回归可通过以下脚本重跑。

```powershell
powershell -File tests/zu4ev/dpc/run_dynamic.ps1 -Full
powershell -File tests/zu4ev/dpc/run_axi.ps1
powershell -File tests/zu4ev/dpc/run.ps1 -Full
```

物理实现报告中仍有 VCU 参考时钟的 TIMING-4、6、7、27 方法学严重警告，以及共享驱动导致一组 bus-skew 约束被忽略的警告。建立和保持余量较窄。本次 bitstream 的上板验证待完成。

## 清理结果

`build/` 下仅保留 `dpc/`。旧 AE、FFC、H.264、NV12 工程、旧发布镜像、DPC 试验目录及重复仿真缓存已移入 Windows 回收站。当前工程保留必要的源 IP 和生成输出。根目录的旧 `.Xil/` 和 `xsim.dir/` 也已清理。

直接递归删除被自动审批拒绝，改用回收站删除后完成工作区清理。清理清单位于 `build/dpc/verification/cleanup.json`。旧 BOOT/QSPI 镜像随历史构建回收，本次定版硬件产物为当前 bitstream 和布线检查点。
