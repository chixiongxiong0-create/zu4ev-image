# ZU4EV Ibex 64 KiB 存储缩减验证

2026-11-26，Vivado 2025.1，XCZU4EV-SFVC784-2-I。

## 地址和固件

- 程序存储 0x00100000–0x0010FFFF，数据存储 0x00200000–0x0020FFFF，各 64 KiB。
- CPU 诊断邮箱 0x0020E000，JTAG 输入邮箱 0x0020F000–0x0020F7FF，输出邮箱从 0x0020F800 开始。旧地址超出新存储范围，读写返回错误。
- AE 固件程序 5488 B，BSS 26660 B，链接器普通 RAM 区 48 KiB，栈顶 0x0020C000，BSS 末尾 0x00206824，保留 22492 B 栈及增长空间。独立平台固件和集成固件生成的二进制一致。
- UltraRAM 程序区启动复制 16384 字，共 32768 个周期。

## 验证

XSim 内存边界、16 种 byte enable、AXI 对齐和回压、CPU 自检、真实 UltraRAM CPU 和 Loader、804 组 AE 邮箱用例、实时 AE 传感器模型以及板级 UltraRAM 模型回归通过。最初旧 RTL 在 0x00110000 指令边界测试失败，新 RTL 通过。8 路并行综合和部分仿真因工作站内存不足失败，降低并发后重试通过。

## 上板验证

使用 Digilent JTAG 进行易失性 PL 更新。下载 `build/dpc_64k/camera_top.bit` 和对应 LTX，startup HIGH，发现 1 个 JTAG AXI、1 个 MIG 和 1 个 VIO。VIO major_bus、major_int、minor 均为 0。

- 停止原有 AE，交还传感器总线，停止 bridge 并解除 NV12 驱动绑定，传感器 `0x0100` 进入 standby。更新后按 FSBL 0/1/3/7 顺序恢复 pipeline，读回传感器 ID 0130 和 stream=1。
- 板上启动协调脚本完成 ISP/TNR 初始化与 Ibex handoff，owner=1、run=1、grant=1、armed=1、boot_ready=1、fault=0、restart=0。
- 64 KiB 新诊断邮箱读回 magic=49414531、state=3、signature=600dae01、fault/mcause/mepc=0，heartbeat、IRQ 和记录增长。AE mean=95，曝光 0x20d0、增益 0x30。当前稳定场景曝光调整次数为 0。JTAG AXI 读回在地址切换时观察到一次旧数据，使用同地址连续两次读，取第二次结果核对邮箱；该现象尚待单独诊断。
- Windows UVC 经 H.264 解码采集 `build/dpc_64k/verification/board/new_capture.png`，1280×1024。另一次连续解码 360 帧成功，FFmpeg 报告约 114.5 fps（含启动开销），dup/drop 均为 0。板端 capture=8516→9116，DP flips=8487→9087，实际约 120 fps，invalid=0。
- 热更新过程中旧 NV12 模块需要先解绑，VCU 驱动卸载出现时钟告警，重新加载后工作。旧 USB gadget 需 stop 后重建才能重新枚举。初始 H.264 复制捕获缺少 SPS/PPS，直接解码抓帧及连续解码成功。最终累计 USB buffer error=1，DQ/event/send/owner error 均为 0；本次不宣称长时间 USB 无错误。

新 PL 保持运行，未改写 QSPI。动态 DPC 仍处于复位默认旁路，未专门执行修复画质测试。
