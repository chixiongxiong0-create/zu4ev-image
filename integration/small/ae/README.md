# AE shadow kernel and reproducible comparison

`ae_core.c` and `ae_core.h` are unchanged copies of the R5 policy source; provenance.json records hashes and the existing R5 ELF. Ibex executes propose/commit on explicitly supplied state. This firmware has no IIC/sensor access. R5 retains sole ownership of IIC0 and normal closed-loop AE. The comparison is captured-frame replay over JTAG; it is not a continuous120fps statistics-input integration or a replacement sensor-control application.

The selected board RAM implementation is256KiB UltraRAM, common100MHz clock. AXI writes are opt-in using EnableInputMailbox; the default reusable system remains read-only. When enabled, only word-aligned0x0023F000..0x0023F7FF writes succeed, honoring WSTRB. All other writes return SLVERR. Output area0x0023F800..0x0023FFFF remains host-read-only. A same-word native CPU read OR write delays the host write; queued writes have priority over new AR reads on port B. R responses already issued remain stable under backpressure. No cross-port collision value is relied on.

Input word0 is the odd/even publish version. Words1..13 are case ID, last_stats_seq, last_write_fe, exposure, max_exposure, fine_gain, initialized, have_write, fe_seq, stats_seq, mean, valid, commit. Host publishes odd version, fills payload, then publishes nonzero even version. Ibex copies and rechecks the version before computing. Output word0 uses the same odd/even protocol. Words1..13 are case ID, change kind, proposed exposure, proposed fine gain, last_stats_seq, last_write_fe, committed exposure, max_exposure, fine_gain, initialized, have_write, elapsed CPU cycles, consumed input version. Output word15 is ready magic0x41454942; a trap replaces it with0xBAD0AE00 and word16 holds mcause. Firmware stack grows down from0x0023E000, leaving an additional4KiB guard before the mailbox. Logical ROM/RAM capacities remain256KiB each.

Build with `tools/build_ae_firmware.sh` in the existing WSL RTL environment. `python ae/make_vectors.py` compiles the unchanged policy with a host compiler, produces boundary/holdoff/wrap/sequence vectors and verifies captured R5 record decisions. `ae/live_fixture.json` preserves the stable captured frame/state input and real R5 kind/code fields for reproduction after cleaning build outputs. Existing raw snapshots, if present in build/ibex_small/ae_live, are decoded using the bounded published ring-index interval; slots overwritten during the read are excluded. Private state values such as last_write_fe/have_write are taken from the actual R5 core snapshot when reconstructing settled records. Host-reference boundary cases must be distinguished from real R5 hardware decisions.

`tools/run_ae_xsim.tcl` runs the actual Ibex+XPM UltraRAM firmware against all vectors through AXI. `ae/generate_board_compare.py` produces the equivalent auditable JTAG script in build/ibex_small/ae/compare_board.tcl. It verifies all proposal/state fields and stable output versions, not just a PASS magic.

The board source uses the local UltraScale+ clock-gate binding directly. `board/ram_boot_and_capture.tcl` is based on the existing recoverable RAM boot flow and adds an immediate non-halting R5 startup snapshot. It does not write QSPI. It temporarily restarts PS/Linux and uses the matching PL bitstream/R5 ELF. Close the Vivado hardware target before PS reset to avoid polling a disappearing debug hub; reconnect only after boot has completed. Restore images and snapshots are stored only in this repository's build tree. Follow RESULTS.md for actual observed scope and limitations.
